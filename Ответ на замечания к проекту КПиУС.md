# Ответы на замечания к проекту КПиУС

## Замечание 1: Интеграция с 1С и позиция учебного блока

> *"Использование платформы является альтернативой 1С, но она вряд ли будет поддержана учебным блоком из-за безопасности и тесной интеграции университета с 1С. Как пример, из последнего, появилась удобная система с расписанием, но ее не признает учебный блок, хотя и в тихушку показывает. Можно рассчитывать на такое же."*

### Корректировка подхода:

1. **Позиционирование системы как надстройки, а не замены 1С**
   - Система КПиУС будет разработана как дополнительный слой, интегрируемый с 1С, а не как его альтернатива
   - Предлагается реализовать двустороннюю синхронизацию данных между КПиУС и 1С:
     - Автоматическая выгрузка итоговых оценок в 1С
     - Импорт базовых данных о студентах и группах из 1С
     - Отправка статистики посещаемости в корпоративную систему

2. **Повышение безопасности**
   - Внедрение дополнительных мер безопасности:
     - Использование единой системы аутентификации университета (SSO)
     - Шифрование всех каналов передачи данных
     - Регулярный аудит безопасности
     - Полное соответствие внутренним политикам безопасности ДВФУ

3. **Стратегия внедрения**
   - Пилотное внедрение на одной кафедре для демонстрации эффективности
   - Постепенное расширение использования с документированием результатов
   - Привлечение представителей учебного блока к процессу тестирования и оценки системы

4. **Акцент на преимуществах для учебного блока**
   - Улучшение качества и полноты данных в 1С за счет более регулярного ввода информации
   - Снижение административной нагрузки на сотрудников учебного блока
   - Предоставление более детальной аналитики для принятия управленческих решений

## Замечание 2: Мотивация преподавателей и студентов

> *"Нужно чтобы студенты мотивировали преподавателей использовать систему. Если не будет ставить оценки — высокая вероятность отчисления — студент заставит преподавателя проставить. Если преподаватель не ставит оценки — значит пропустил пару."*

### Механизмы мотивации и контроля:

1. **Геймификация для преподавателей**
   - Внедрение рейтинга активности преподавателей с публичным признанием
   - Система достижений и статусов в зависимости от регулярности использования
   - Интеграция с системой KPI кафедр

2. **Автоматические уведомления**
   - Система напоминаний о необходимости выставления оценок
   - Эскалация уведомлений заведующему кафедрой при длительном игнорировании
   - Автоматические отчеты о пропущенных занятиях преподавателями (на основе отсутствия отметок о посещаемости)

3. **Контроль со стороны студентов**
   - Создание механизма запросов на выставление оценок через личный кабинет
   - Возможность анонимных уведомлений о невыставленных оценках
   - Статистика доступности оценок по предметам для деканата

4. **Механизм "двойной ответственности"**
   - Если преподаватель не отмечает посещаемость, система автоматически регистрирует это как пропуск пары преподавателем
   - Эта информация становится доступной заведующему кафедрой и включается в статистические отчеты

## Замечание 3: QR-коды для отметки посещаемости

> *"Для массового проставления посещаемости генерировать QR (Под капотом апи, берет пользователя и сопоставляет с тем, что преподаватель создал). Не более 2-3 минут, чтобы избежать пересылки."*

### Реализация функционала QR-кодов:

1. **Процесс отметки посещаемости**
   - В начале занятия преподаватель генерирует уникальный QR-код для текущей пары
   - Код содержит зашифрованную информацию о дисциплине, группе, преподавателе и временную метку
   - Действие кода ограничено 2-3 минутами для предотвращения мошенничества
   - Возможна регенерация кода в случае необходимости

2. **Безопасность и защита от обхода**
   - Привязка проверки QR-кода к геолокации аудитории
   - Ограничение по IP-адресу в пределах сети университета
   - Использование динамических QR-кодов с уникальными токенами для каждого занятия
   - Логирование всех попыток отметиться и выявление аномальных паттернов

3. **Альтернативные методы отметки**
   - Ручное отмечание преподавателем для случаев технических сбоев
   - Возможность биометрической авторизации в будущих версиях
   - Интеграция с системами контроля доступа в аудитории (турникеты, электронные замки)

4. **Удобство использования**
   - Возможность массовой отметки всей группы как присутствующей с последующей корректировкой только отсутствующих
   - Предварительная загрузка списка студентов по расписанию
   - Автоматическое определение текущего занятия на основе времени и расписания преподавателя

## Общий план корректировки проекта

1. Пересмотреть архитектуру системы, заложив в основу интеграцию с 1С
2. Дополнить модуль авторизации поддержкой корпоративной системы аутентификации ДВФУ
3. Разработать детальные спецификации API для интеграции с существующими системами
4. Создать прототип системы мотивации преподавателей и студентов
5. Реализовать полнофункциональный модуль QR-аутентификации с учетом всех требований безопасности

Эти изменения позволят учесть все полученные замечания и значительно повысят шансы системы на успешное внедрение в учебный процесс ДВФУ.
